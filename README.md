# Учёт изделий — мобильное web-приложение для цеха

Штучный контроль движения изделий по операциям с поддержкой сканирования штрих-кодов
камерой телефона/планшета. Адаптивный интерфейс mobile-first, без сборки и фреймворков
на фронте.

## Возможности

- **Роли**:
  - **Рабочий** — продвижение изделий на следующую операцию.
  - **Бригадир** — продвижение, откат на предыдущую операцию, отправка в брак,
    управление составом своей бригады (добавление/исключение рабочих).
  - **Мастер** — запуск изделий в производство, продвижение, откат, отправка в брак,
    возврат из брака, создание номенклатур, создание/удаление/переименование
    бригад, назначение бригадиров, управление составом любой бригады.
  - **Администратор** — создание пользователей, смена роли, сброс пароля,
    включение/отключение учётных записей.
- **Бригады**: каждая бригада имеет одного бригадира и набор рабочих; рабочий
  состоит максимум в одной бригаде.
- **Номенклатуры** с произвольным набором последовательных операций (маршрут).
- **Изделия** с уникальным серийным номером и штрих-кодом, привязкой к номенклатуре
  и текущей операции.
- **Сканирование штрих-кода** камерой устройства (ZXing) — EAN/UPC/Code128/Code39/QR.
- **Полная история** перемещений по каждому изделию (кто, когда, какое действие,
  переход между операциями, комментарий).
- **Хранение в PostgreSQL**, транзакции для целостности.

## Стек

- Backend: Node.js 20+, Express, `pg`, `bcryptjs`, JWT.
- Frontend: vanilla JS, без сборки, ZXing-browser (через CDN).
- DB: PostgreSQL 13+.

## Быстрый старт

```bash
cp .env.example .env            # отредактируйте при необходимости
docker compose up -d            # поднимает PostgreSQL
npm install
npm run init-db                 # создаёт таблицы
npm run seed                    # тестовые пользователи и номенклатуры
npm start
```

Откройте `http://localhost:3000` (на телефоне — `http://<IP-сервера>:3000`).
Камера в браузерах работает только по **HTTPS** (или с `localhost`). Для тестов
с реального телефона используйте HTTPS-туннель (например, `cloudflared`, `ngrok`)
или разверните за обратным прокси с TLS.

### Тестовые учётные записи

| Логин   | Пароль       | Роль      |
|---------|--------------|-----------|
| worker  | worker123    | Рабочий   |
| foreman | foreman123   | Бригадир  |
| master  | master123    | Мастер    |
| admin   | admin123     | Администратор |

### Тестовые номенклатуры

- `VAL-001` Вал ведущий — 6 операций.
- `KOR-002` Корпус редуктора — 6 операций.

## API (кратко)

- `POST /api/auth/login` `{username, password}` → `{token, user}`
- `GET  /api/nomenclatures` — список с операциями
- `POST /api/nomenclatures` (master) — создание
- `GET  /api/items?status=&nomenclature_id=&q=` — список
- `GET  /api/items/lookup/:barcode-or-id` — карточка + история + маршрут
- `POST /api/items` (master) — запуск нового изделия
- `POST /api/items/:id/action` `{action, note}` —
  `advance` (worker/foreman/master), `rollback` (foreman/master),
  `scrap` (foreman/master), `return_from_scrap` (master).
- `GET  /api/brigades` (foreman/master) — список бригад
- `GET  /api/brigades/:id` — состав бригады
- `POST /api/brigades` (master) — создание бригады
- `PATCH /api/brigades/:id` (master) — переименование, смена бригадира
- `DELETE /api/brigades/:id` (master) — удаление
- `POST /api/brigades/:id/members` `{user_id}` — добавить рабочего
  (master — в любую; foreman — только в свою)
- `DELETE /api/brigades/:id/members/:user_id` — исключить (правила те же)
- `GET  /api/users?role=worker|foreman[&include_inactive=1]`
  (foreman/master/admin) — список пользователей
- `POST /api/users` (admin) — создание пользователя
- `PATCH /api/users/:id` (admin) — обновление ФИО, роли, пароля, статуса

Все защищённые эндпоинты требуют заголовок `Authorization: Bearer <jwt>`.

## Логика операций

Каждая номенклатура задаёт упорядоченный список операций `seq=1..N`. Изделие
после запуска находится на операции `seq=1`. Продвижение перемещает на следующую
операцию; продвижение с последней операции переводит статус в `completed`. Откат
возвращает на предыдущую операцию (с первой невозможен). Отправка в брак ставит
статус `scrapped`. Возврат из брака возвращает изделие на ту же операцию со
статусом `in_progress`. Все действия атомарно записываются в `movements`.
